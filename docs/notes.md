# 调试记录（notes.md）

> 每次改了检索/提示词，记一条：改了什么 → 指标怎么动 → 为什么。这是面试最值钱的素材，
> 因为它证明系统是**调**出来的，不是拼出来的。

## 2026-11-03　评测集与检索三连改

### 基线

| 评测集 | 题量 | Recall@5（改动前） |
|---|---|---|
| `eval/qa_set.jsonl`（教科书式，用了法条词汇） | 23 | 100% |
| `eval/qa_set.hard.jsonl`（口语化，无术语） | 10 | 80% |

**先注意 100% 这件事**：题目直接用了法条原词（「试用期最长可以约定多久」≈ 第十九条原文），
检索当然百发百中。**这种题集的指标不能写进简历**，它测的是"能不能查到已经知道的东西"。

### 改动 1：gold 多金标注（只改标注，不改代码）

- `怀孕了公司想让我辞职` 的 gold 加上《女职工劳动保护特别规定》第五条（同样规定不得因孕辞退）
- `末位淘汰` 的 gold 加上司法解释（二）第十八条
- 结果：口语集 60% → 80%

**教训**：一个问题的正确答案往往不止一条。gold 只写一条，会把答对的系统判成失败，
指标被人为压低。标注时要问"只引这条算不算答对"。

### 改动 2：法律术语词典 + 查询扩展（`src/tokenize.py`、`src/retrieve.py`）

- 给 jieba 加 60 个法律术语（经济补偿、加班费、百分之一百五十、竞业限制……），
  因为「百分之一百五十」会被切成 `百/分/之/一/百/五/十`，BM25 直接失效
- 建索引和查询都改用同一个 `cut()`，否则两套切词对不上
- 加口语映射：一倍半→加班费/延长工作时间、调到→变更劳动合同/工作地点、末位淘汰→不能胜任工作

结果：**口语集 80% → 80%，零提升；教科书集 100% 保持**。

### 改动 3：重排分数与 RRF 加权融合 → 回滚

失败样本 `上个月加班费按一倍半给我算的`（gold = 劳动法第四十四条）追踪链路：

```
向量召回 rank 1 / BM25 rank 1 / RRF rank 1  →  重排后掉出前 5
```

**检索没错，是 reranker 把正确答案挤掉了。** 试了两个修法：

| 修法 | 结果 |
|---|---|
| 把《法律名》条号拼进重排文本 | 无效（gold 仍在前 5 外） |
| 重排分数 0.5 + RRF 分数 0.5 加权 | 口语集仍 80%，教科书集 **掉到 95.7%** → 回滚 |

结论：`bge-reranker-v2-m3` 对"中文口语 ↔ 法条书面语"的跨域匹配弱，是当前瓶颈。
真正要解决得换更强的重排模型或做 query 改写，不是调融合权重。

### 当前状态

| 评测集 | Recall@5 |
|---|---|
| 教科书式 23 题 | 100% |
| 口语化 10 题 | 80% |

### 下一步

1. 把口语集扩到 40–80 题（现在 n=10，一题就是 10 个百分点，指标噪声太大）
2. 做 query 改写（口语问题 → 检索式），比换重排模型便宜
3. 有了稳定评测集，再跑 `python eval/ablate.py` 出消融表

## 2026-11-03（续）消融实验：等权 RRF 在拖后腿

跑 `eval/ablate.py`（40 题口语集）得到：

| 方案 | Recall@5 |
|---|---|
| ① 纯向量 | 72.5% |
| ② 纯 BM25 | 42.5% |
| ③ 混合 RRF（等权） | **52.5%**（低于纯向量！） |
| ④ 混合 + 重排（等权） | 80.0% |
| ⑤ 纯向量 + 重排 | **82.5%** |

**反直觉的地方**：等权 RRF 融合后，混合检索（52.5%）比纯向量（72.5%）还差 20 个百分点。
原因是 BM25 在这批口语题上只有 42.5%，RRF 等权相加等于把弱信号按同等分量掺进强信号里。
而重排（cross-encoder）一下把混合拉回 80%、把纯向量拉到 82.5% —— **真正起作用的是重排，不是"混合"这个动作本身。**

处置：把 RRF 改成加权（向量 0.8 / BM25 0.2），结果 ③ 52.5% → 65.0%，④ 80.0% → 82.5%，
与纯向量+重排打平，不再拖后腿。

**记下来备面试**：不要说"我用了混合检索所以效果好"（数据不支持）；
要说"我做了消融，发现等权 RRF 反而有害，把权重调成 0.8/0.2 才不掉分，
这套语料上语义检索已够用，BM25 的价值在长尾精确术语，当前题集没测到"。

## 2026-11-04 合同审查 v2：closed-set 引用 + 多问题拆分

两个 v1 的已知问题都修了，指标反而全升：

| 指标 | v1 | v2 |
|---|---|---|
| 埋点召回 | 18/19（94.7%） | **19/19（100%）** |
| 高风险误报（D） | 0 | 0 |
| 引用有效率 | 100%（只证明存在） | 100%（closed-set：只准引候选编号，按编号反查） |
| 摘录逐字率 | 无此指标 | 97.7%（44 条引用逐字比对，1 条不符自动标出） |

**三个真正的改动（按贡献排序）：**

1. **closed-set 引用**：候选法条编号 `[1]..[6]` 喂给模型，输出只准用 idx，后端按编号反查重建
   (法律名, 条号)。这从**结构**上消灭了"编一个库里真实存在但法理不对"的引用——
   旧版校验查存在性，查不出"引错"；新版引用只能来自检索候选，候选外引用和「依据不足」
   都会被显式计数。**启示：防幻觉别靠校验兜底，把输出空间直接锁死更便宜。**
2. **多问题拆分**：v1 的单对象 schema（一个条款一个 risk_level）是 B1 漏检的根因——
   同一条款两个坑在结构上就只能报一个。改成 issues[] 后 B1 判高并正确引第 19 条。
   **启示：漏检有时候不是模型能力问题，是输出格式把答案挤掉了。**
3. **合同期限背景**：试用期上限取决于合同期限，单审一条时模型看不见第一条。
   把期限条款作为背景传给每条审查，B1 从含糊的"中"变成明确的"高"。
   **启示：逐条审查的粒度选择要考虑跨条款依赖，必要时注入上下文。**

**过程中试过但没用的：** 提示词里写"禁止性条文优先于责任性条文"——A5 仍引 31/90 而不是 25。
说明法理选择偏好很难靠 prompt 纠正，根因在检索排序（25 条排第 6）。这就是 v2 留下的
头号已知局限，也是"下一步做违约金/押金类 query 检索增强"的动机。

**记下来备面试（v2 版说法）：**
"v1 我发现引用校验只查存在性，防不住引错条。v2 我把候选法条编号喂给模型、只准按编号引用，
从结构上锁死输出空间；同时把单对象输出改成数组，修掉了同条款多问题的漏检。
埋点召回从 94.7% 到 100%，还新增了摘录逐字核验指标——每条引用的'原文摘录'和条文原文
逐字比对，44 条里 1 条不符会被自动标红。这个指标是抄袭检测思路的移植。"

**留下的新已知局限（都写进 README 了）：**
1. closed-set 保证"来自候选"，不保证"选了候选里最对的"（A5 案例）
2. 多问题拆分偶有语义重复（B2 的"未约定补偿"vs"约定无需支付"）
3. 文件头"甲方/乙方"块被当独立条款审，报一条"必备条款缺失"的中风险
