**标为"高/中"且命中同一个坑才算召回。** 自己数，不要让模型自己判断。

## v2 相对 v1（2026-11-03）改了什么

1. **closed-set 引用**：候选法条带编号 `[1]..[6]` 喂给模型，模型只能用 `idx` 引用，
   后端按编号反查重建 `(法律名, 条号)`。旧版模型可以自由写法条名（只要库里存在就通过），
   所以引得出"真实存在但法理不对"的条文；v2 从结构上杜绝了编造，且查不到依据时如实标「依据不足」。
2. **同条款多问题拆分**：输出 schema 从单对象改为 `issues[]`。v1 的 B1 漏检
   （试用期 6 个月超上限 + 试用期工资过低同在一条，只报了后者）根因就是单对象 schema。
3. **合同期限背景**：试用期上限取决于合同期限（一年期上限 2 个月），单审一条时模型看不见第一条，
   v1 只能含糊报"中"。v2 每条审查都带上合同期限条款作背景，B1 判"高"并正确引第十九条。
4. **摘录逐字核验**：每条引用的 quote 与所引条文原文逐字比对（抹掉空白/标点），不符自动标出。
5. 候选从 top4 放宽到 top6；模型进度输出改到 stderr，stdout 只剩纯 JSON（可直接管道给 `json.load`）。

## 仍存在的问题（面试可讲）

1. **closed-set 只保证"引用来自候选"，不保证"选了候选里最对的那条"。**
   A5（违约金条款）模型引了劳动法第31条（提前30日书面通知）+ 劳动合同法第90条（劳动者违法解除的赔偿责任）——
   两条都在候选内、法理上沾边（提前解除是法定权利），但最直接的其实是候选里排第 6 的劳动合同法第25条
   （除服务期/竞业外不得约定由劳动者承担违约金）。检索排序把"通知/责任"类条文排在"禁止"类条文前面是根因之一。
   改进方向：给违约金/押金类 query 做检索增强，或让模型对候选条文做一轮法理排序。
2. **文件头噪音**：合同开头的"甲方/乙方"信息块被当作独立条款审查，会报一条"必备条款缺失"的"中"。
   根因是按条切分把非条款文本也切进去了；改进方向是识别并跳过前导信息块。
3. **拆分偶有语义重复**：B2 的"未约定补偿"与"约定无需支付补偿"本质是同一个坑的两个表述。
   多问题拆分宁可略多不可漏检，属于可接受的权衡。

## 复现方法

```powershell
python -m src.review data/contracts/合同A-科技公司.txt
```

进度信息走 stderr，stdout 是纯 JSON，可直接 `| python -c "import json,sys; ..."` 解析。

注意：合同放在 `data/contracts/`，**不能放 `data/raw/`**，否则会被 `src/ingest.py` 当成法规切进知识库。
